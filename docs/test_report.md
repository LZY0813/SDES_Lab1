# S-DES 五关测试与结果分析报告

## 1. 测试概况

本项目按照课程文档给出的 P-Box、S-Box 和两轮 Feistel 流程实现。密钥扩展采用：

```text
Ki = P8(Shift^i(P10(K))), i=1,2
```

即 K1、K2 均从 P10 结果出发，分别独立循环左移 1 位和 2 位。

| 项目 | 结果 |
|---|---:|
| Python 自动化测试 | 33 项通过，0 失败 |
| GUI 自动操作 | 15 项通过 |
| 全域加密组合 | 1024×256=262144 |
| Python/JavaScript 一致 | 262144 |
| 双向解密检查 | 524288 |
| 不一致或往返错误 | 0 |

测试环境与时间记录见 [environment.json](../results/environment.json)，可复现结果见 [results](../results/)。

## 2. 第1关：基本加解密

### 2.1 测试目标

- GUI 接收 8-bit 明文或密文；
- 接收 10-bit 主密钥；
- 加密输出 8-bit 密文；
- 解密恢复原始明文；
- 保留前导零并拒绝非法输入。

### 2.2 逐轮测试向量

| 项目 | 值 |
|---|---|
| 明文 P | `11010111` |
| 密钥 K | `1010000010` |
| K1 | `10100100` |
| K2 | `10010010` |
| IP(P) | `11011101` |
| 第1轮输出 | `00101101` |
| SW | `11010010` |
| 第2轮输出 | `10110010` |
| 密文 C | `11101000` |
| 解密结果 | `11010111` |

逐位置换、EP、XOR、SBox和SP计算见 [algorithm_spec.md](algorithm_spec.md)。

### 2.3 全域往返

对全部 1024 个密钥和 256 个明文执行：

```text
D(K, E(K, P)) = P
```

共检查 262144 个组合，全部通过；每个固定密钥对 256 个明文形成双射。

![第1关二进制加解密](../results/screenshots/01_binary.png)

**第1关结论：通过。**

## 3. 第2关：交叉测试

### 3.1 独立实现全域验证

主程序使用 Python 整数位运算；参考程序使用 JavaScript 位数组。两套代码分别实现置换、SBox、密钥扩展和两轮加解密，不互相调用算法函数。

两套实现按照“密钥从 0 到 1023、明文从 0 到 255”的固定顺序生成全部密文字节，摘要完全一致：

记录数：262144

不一致：0

## 4. 第3关：ASCII 字符串

### 4.1 实现

每个 ASCII 字符编码为一个字节，独立执行 S-DES。密文可能包含不可显示字节，因此 GUI 使用 HEX 展示，并支持导出原始 `.bin` 文件。

### 4.2 示例

```text
明文：This is a pen
字符数：13
密文长度：13 byte = 104 bit
HEX：82 0C 83 63 C2 83 63 C2 F9 C2 4F 5C 7E
解密：This is a pen
```

参考仓库 README 将该字符串写成 112 bit；按实际13个字符计算应为104 bit。双方算法生成的底层密文字节一致，只是对方展示连续二进制，本项目展示 HEX。

测试还覆盖空字符串、空格、标点、LF/CR/TAB、全部 0–127 ASCII 字符、非法 HEX和非 ASCII 输入。

![第3关 ASCII](../results/screenshots/02_ascii.png)

**第3关结论：通过。**

## 5. 第4关：暴力破解

### 5.1 方法

遍历 `0000000000` 到 `1111111111` 全部 1024 个密钥。每个候选必须同时满足用户输入的全部明密文对，程序不会找到第一个候选后提前停止。

计时使用 `perf_counter_ns()`；另记录带时区的开始与结束时间。完整结果可导出 JSON。

### 5.2 单组明密文实验

```text
P = 11010111
C = 11101000
```

候选共6个：

```text
0010110100  0110110100  1001011011
1010000010  1101011011  1110000010
```

GUI 实际检查 1024 个密钥，计算耗时约 `0.005923600 s`。不同运行负载下时间会波动。

### 5.3 增加明密文对

| 明密文对数量 | 候选数量 |
|---:|---:|
| 1 | 6 |
| 2 | 2 |
| 3 | 2 |
| 4 | 2 |
| 5 | 2 |
| 6 | 2 |
| 7 | 2 |

加入第二对后只剩 `1010000010` 和 `1110000010`。继续加入本次选择的样本也不能继续缩小，原因见第5关等效密钥分析。

![第4关破解结果](../results/screenshots/03_brute_force.png)

![第4关真实操作过程](../results/recordings/brute_force.gif)

**第4关结论：通过；一组明密文不能唯一确定密钥。**

## 6. 第5关：封闭测试

### 6.1 抽屉原理

固定任意明文 P 后，密钥空间有1024个元素，密文空间只有256个元素。映射：

```text
K → E(K, P)
```

必然存在不同密钥映射到同一密文。

### 6.2 完整枚举结果

对全部256个明文和1024个密钥执行262144次加密：

| 指标 | 结果 |
|---|---:|
| 每个明文出现的不同密文 | 254 |
| 每个明文的不可达密文 | 2 |
| 单个明密文对最大候选数 | 8 |
| 不同完整密钥映射 | 512 |
| 等效密钥组 | 512组，每组2个 |

完整逐明文数据见 [collision_statistics.csv](../results/collision_statistics.csv)。

### 6.3 全域等效密钥

```text
K₁ = 1010000010
K₂ = 1110000010
```

这两个不同主密钥对全部256个明文产生完全相同的密文。它们不是只在某个明文上碰撞，而是完整加密函数相同。因此：

- 任何数量的明密文对都无法区分这两个主密钥；
- 暴力破解最终保留两个候选不是程序错误；
- 本密钥调度实际只能产生512种不同加密映射。

### 6.4 指定明密文对

指定明密文对可能：

- 不可达，对应0个密钥；
- 对应多个密钥；
- 在本密钥扩展规则下，不存在只对应1个密钥的明密文对。

![第5关碰撞分析](../results/screenshots/04_collisions.png)

**第5关结论：存在局部碰撞和全域等效密钥；仅靠明密文对不能保证唯一恢复10-bit主密钥。**

## 7. 代码质量与可复现性

- 核心、分析和 GUI 分层；
- 对外输入进行长度、字符、ASCII和HEX校验；
- 耗时任务放在 QThread 中，GUI保持响应；
- 测试覆盖固定向量、非法输入、全部加解密组合、破解和碰撞统计；
- 结果文件可由 `scripts/validate.py` 重建；
- 截图和 GIF 由 `scripts/capture_gui.py` 操作真实 Qt 窗口生成，且只捕获本程序客户区。
